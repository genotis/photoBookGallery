# 01. 요구사항 정의서

## 1. 목적

시놀로지 NAS에 축적된 다수의 사진집/그라비아 압축 파일을, 파일을 일일이 풀지 않고도
웹 브라우저에서 **탐색(Browse) → 정리(Organize) → 감상(Gallery View)** 할 수 있는
셀프호스팅 애플리케이션을 만든다.

## 2. 사용자 / 운영 환경 가정 (확정)

- **사용자 규모**: **단일 사용자, 본인 시스템에서 혼자 사용.** 다중 사용자/RBAC 불필요.
  인증은 외부 노출 대비 최소 게이트(단일 비밀번호)면 충분.
- **운영 위치**: Synology NAS 내 Docker 컨테이너. 외부 노출은 NAS의 리버스 프록시
  또는 VPN 경유를 가정.
- **데이터 규모(초기 가정)**: 압축 파일 수천~수만 개, 파일당 수십~수백 장 이미지.
  → 인덱싱/썸네일 전략이 성능의 핵심.
- **콘텐츠 특성**: 일본 그라비아가 주. **모델(인물)** 이 가장 중요한 분류 축.

## 3. 기능 요구사항 (Functional)

### FR-1. 라이브러리 탐색 (Browse)
- NAS의 지정된 루트 경로(들)를 스캔하여 압축 파일을 자동 인덱싱.
- 폴더 트리 탐색 + 분류 축(국가/출판사/모델/시리즈/태그)별 탐색.
- 파일명/메타데이터 기반 검색, 정렬(이름/날짜/크기/페이지수/추가일).
- 페이지네이션 또는 무한 스크롤.

### FR-2. 갤러리 뷰잉 (강화 영역)
- **썸네일 그리드**: 가상 스크롤(virtualized) 기반 대량 썸네일 렌더링.
  표지(첫 이미지) 또는 대표 이미지 지정 가능.
- **뷰어(라이트박스)**: 압축파일 내 이미지를 페이지 단위로 순차 열람.
  - 키보드/스와이프 네비게이션, 프리로딩(다음 페이지 선읽기).
  - 보기 모드: 단일 페이지 / 더블 페이지(좌우 펼침) / 연속 스크롤(웹툰식).
  - 줌/팬, 화면맞춤(fit-width/height/original), 회전.
  - 슬라이드쇼(자동 넘김, 간격 설정).
- **자연 정렬(natural sort)**: `2.jpg`가 `10.jpg`보다 앞에 오도록 페이지 순서 보정.

### FR-3. 정리 / 메타데이터 관리 (Organize)
- 압축파일 단위로 메타데이터 부여/수정:
  - 국가(Country), 출판사·제작주체(Publisher/Producer), 모델(Model, 다대다),
    시리즈(Series), 발행일, 태그, 평점, 즐겨찾기, 메모.
- **파일명 자동 파싱**: 일본 그라비아 명명 관례에서 모델명/제작주체/호수 추정,
  사용자 확인 후 확정(휴리스틱 + 수동 보정).
- 모델/출판사 엔티티를 별도 관리 (별칭, 프로필 이미지, 설명).
- 일괄 편집(배치 태깅), 중복 탐지(파일 해시 기반).

### FR-4. 압축파일 직접 읽기
- 압축 해제 없이 엔트리 목록 조회 및 개별 이미지 스트리밍.
- 지원 포맷: `.zip`, `.cbz`(=zip), `.cbr`(=rar), `.rar`. (확장 시 `.7z`, `.tar`)

### FR-5. 압축파일 내 개별 파일 삭제 후 재압축
- 뷰어/관리 화면에서 불필요한 페이지(이미지) 선택 → 삭제 → 아카이브 재생성.
- **저장 정책(확정)**: **원본을 백업 경로로 보관한 뒤, 활성 위치를 새 ZIP(.cbz)으로
  교체**한다. ZIP 원본도 동일하게(백업 후 교체), CBR/RAR은 RAR 쓰기가 불가하므로
  결과가 항상 `.cbz`로 바뀐다. 상세: [04-archive-handling.md](04-archive-handling.md).
- 작업은 임시 파일에 먼저 생성 후 검증 → 원본 백업 → 원자적 교체로 데이터 손실 방지.

### FR-6. 시스템/운영
- 백그라운드 인덱싱 작업 큐 + 진행 상황 표시.
- 썸네일 캐시 관리(생성/무효화/용량 제한).
- 간단한 인증(최소 단일 비밀번호 또는 사용자/세션). 외부 노출 대비.

## 4. 비기능 요구사항 (Non-Functional)

| 항목 | 요구 |
|------|------|
| 성능 | 썸네일 그리드 첫 표시 < 1s(캐시 적중 시). 뷰어 페이지 전환 체감 즉시(프리로딩). |
| 확장성 | 수만 개 아카이브 인덱싱 가능. DB 인덱스/페이지네이션 필수. |
| 안정성 | 편집 시 원본 무손실(원자적 쓰기, 실패 시 롤백). |
| 이식성 | NAS Docker 단일 컨테이너로 구동. amd64/arm64 멀티아키 이미지. |
| 보안 | 인증 게이트, 경로 탈출(path traversal) 차단, 미디어 경로 화이트리스트. |
| 권한 | Synology 볼륨 권한(PUID/PGID) 대응. 미디어는 기본 RO, 편집 대상만 RW. |
| 관측성 | 구조적 로깅, 인덱싱/편집 작업 상태 조회. |

## 5. 범위 밖 (Out of Scope, 초기)
- 영상 파일 트랜스코딩/스트리밍.
- 외부 메타데이터 자동 수집(스크래핑) — 추후 플러그인으로 검토.
- 다중 테넌트/세밀한 권한(RBAC) — 추후.
- 모바일 네이티브 앱 — 초기엔 반응형 웹으로 대응.

## 6. 확정된 결정사항
1. **사용자/인증**: 단일 사용자(본인). 단일 비밀번호 게이트로 충분.
2. **아카이브 식별**: **내용 해시 기반**(BLAKE3/xxHash64). 파일 이동/리네임에도
   메타데이터 유지. 전체 해시는 1회 계산 후 `(크기,mtime)`로 캐시. → [05](05-data-model.md)
3. **편집 저장 정책**: **원본을 백업 경로로 보관 후, 활성 위치를 새 ZIP으로 교체.**
   → [04](04-archive-handling.md)
4. **DB**: 초기 SQLite + Prisma (단일 사용자에 충분, 필요 시 Postgres 승격).
